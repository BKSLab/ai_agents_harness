# Чек-лист рисков

Используй применимые разделы. Для high-risk просмотри все восемь, а в результате оставь существенные риски, неизвестное и обоснованные исключения. Связывай записи с требованиями и проверками устойчивыми ID. Перечень пунктов сам по себе не доказывает, что риск проверен.

## Контракты

- REST API: новые/изменённые эндпоинты, поля запроса и ответа, коды ошибок. Обратная совместимость для существующих клиентов.
- Схема БД: миграции, обязательность полей, значения по умолчанию для существующих строк.
- Очереди, события, фоновые задачи: формат сообщений, порядок обработки, повторная доставка.
- Файловые форматы и экспорт: старые файлы читаются новой версией, новые — старой.

## Потребители

- Кто вызывает изменяемое: сервисы, админки, внешние клиенты, планировщики.
- Контракт задокументирован у потребителя? Изменение требует синхронного релиза?
- Как потребитель узнает об изменении: версия API, changelog, личное уведомление.

## Данные

- Миграция на большом объёме: время, блокировки, откат.
- Существующие данные под новыми правилами валидации — не сломаются ли чтение и запись.
- Персональные данные и секреты: не появляются ли в логах, ответах, экспорте.

## Конкурентность и идемпотентность

- Параллельные запуски одной операции: блокировки, гонки, двойная запись.
- Повтор запроса (ретрай клиента, дубль webhook): результат тот же, без второго эффекта.
- Частичный сбой в середине цепочки: состояние консистентно, восстановление описано.

## Внешние системы

- Таймауты, повторы, деградация при недоступности каждого внешнего вызова.
- Лимиты API и стоимость: новые вызовы в циклах и на больших объёмах.
- Ответ внешней системы изменился или пустой — поведение определено.

## Совместимость и откат

- Старая и новая версия работают одновременно (катится не всё сразу)?
- Откат релиза: миграции обратимы или описан ручной путь.
- Фича-флаг или конфиг для отключения без передеплоя.

## Наблюдаемость

- Логи: по ним видно, что операция произошла и чем кончилась; без секретов в тексте.
- Метрики/алерты на новый путь отказа.
- Как оператор отличит «работает» от «тихо сломано».
- После прерывания видно, какой шаг завершён, можно ли повторить его и к какой версии кода относится результат.

## Безопасность

- Новые входы пользовательских данных: валидация, экранирование, инъекции.
- Доступ: кто может вызвать новое действие, проверка на каждом пути.
- Секреты: новые значения — только в окружении, имена задокументированы без значений.
