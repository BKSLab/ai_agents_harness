# Машинный вердикт

Контроллер принимает заключение через `task review ID --input FILE`. JSON и YAML имеют одну схему; незнакомые поля и повторяющиеся YAML-ключи отклоняются. Значения снимка и проверки бери из квитанции контроллера, а не из текста автора.

```yaml
schema_version: 1
snapshot_id: SNAPSHOT_ID
fingerprint: SHA256_ИЗ_КВИТАНЦИИ
plan_hash: SHA256_ПЛАНА_ИЗ_КВИТАНЦИИ
verification_id: VERIFICATION_ID
reviewer: reviewer-session-identifier
status: changes_requested
summary: Повтор возврата после потерянного ответа создаёт вторую запись.
findings:
  - id: FINDING-1
    severity: major
    location: app/refunds.py:42
    problem: Повтор операции не проверяет ключ идемпотентности.
    evidence: CHECK-1 на указанном снимке воспроизводит две записи при одном ключе.
    suggestion: Сохранять и проверять ключ операции до внешней записи; повторить CHECK-1.
limitations: []
```

Это иллюстрация, не готовый файл: замени placeholders реальными значениями. `fingerprint` и `plan_hash` — по 64 шестнадцатеричных символа; выдуманный подходящий hash не является свидетельством. Все поля обязательны; без замечаний передай `findings: []`, без ограничений — `limitations: []`.

ID замечания сохраняется между проходами. `evidence` объясняет воспроизводимое условие или цепочку причин; утверждение «плохой паттерн» недостаточно. `suggestion` описывает исправление и способ его проверки. Severity: `blocker` — сдача невозможна, `major` — существенный дефект, `minor` — неблокирующее замечание. Не маскируй обязательную недоступную проверку как minor.

`approved` требует актуальных результатов обязательных проверок и отсутствия blocker/major. `changes_requested` требует конкретного исправления. `blocked` означает существенную нехватку данных или проверки; опиши её в `limitations`. Количество проходов хранится контроллером между сессиями.

Схема task review применяется к управляемой задаче с планом и снимком. При разовом ревью без формального плана выполни проверку доступного diff и сообщи границы в обычном ответе; не создавай фиктивные `plan_hash` и квитанции ради прохождения схемы. Для управляемого цикла сначала потребуется реальный план контроллера.
