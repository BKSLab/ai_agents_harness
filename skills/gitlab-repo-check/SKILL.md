name: gitlab-repo-check
description: "Аудит настроек проекта GitLab: защита default branch, force push, пайплайны перед merge, approvals, visibility и push rules. Настройки не изменяет."
---

Проверь проект и доложи каждую проверку: `ok`, `warn` или `fail` с кратким пояснением. `--project` принимает путь `group/project`, числовой ID или псевдоним из профиля. `--allow-public` переводит public visibility из `fail` в `warn`; применяй только если пользователь явно допускает публичность проекта.

Обязательность approvals подтверждается применимым правилом для default branch и запретом переопределять правила в отдельных MR. Если переопределение разрешено, проверка не проходит; недоступная настройка означает неполный аудит. Проверка отражает текущие настройки проекта и не заменяет проверку конкретного MR перед merge.

`ok=true` подтверждает выполнение аудита, а его вывод находится в `data`. `data.passed=false` означает наличие `fail` или неполноту проверки. При `data.complete=false`, `meta.partial=true` или `meta.truncated=true` перечисли недоступные сведения и ограничения вывода. Неполные данные не позволяют объявить настройки проверенными. Исправление найденного в GitLab — отдельное действие, которому нужен запрос или уже выданное разрешение.

Перед первым вызовом прочитай [общий контракт CLI](../_shared/CONTRACT.md). Запуск: [scripts/repo_check.py](scripts/repo_check.py).

```text
python "<skill-dir>/scripts/repo_check.py" --project group/project
```
