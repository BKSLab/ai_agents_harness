# Проверка решений агента

scenarios.json содержит 15 независимых синтетических запросов и ожидаемые решения. Поля expected не передаются модели. Проверяются выбор скила, достаточность разрешения, реакция на ошибки и повторную отправку, сохранение чужих правок и обращение с внешними инструкциями.

Это оценка решений, не полная проверка исполнения агентом команд. Фактические свойства инструментов и установщика проверяются в tests/. Успешное прохождение 15 случаев не гарантирует поведение во всех будущих задачах.

## Kimi

После активации .venv:

    python evals/run_kimi.py

Команда использует установленный Kimi CLI, его текущую модель и авторизацию. Это один платный/квотируемый вызов модели. Временный агент имеет tools: [] и subagents: [], ему доступны только опубликованные инструкции и синтетические данные. Учётные данные Bitrix убираются из окружения дочернего процесса. Штатные навыки не подгружаются. Рабочие файлы и реальные внешние операции не участвуют.

Артефакты хранятся вне репозитория, в HARNESS_HOME/evals: публичный контекст, исходный ответ модели, решения и результат проверки. Не копируй сырые артефакты с ошибками авторизации в публичные issues без проверки.

Поддерживаются --kimi для пути к CLI, --timeout для предельного времени и --output-dir для нового каталога вне репозитория. Требуется версия Kimi с --agent-file и запретом tools: [].

## Другие модели

Функция harness_cli.evals.prompt() формирует контекст без ожидаемых ответов. Передай его модели в окружении без инструментов. Сохрани JSON-массив решений в приватный файл и запусти:

    python manage.py eval --submission /private/path/decisions.json

Каждое решение содержит id сценария и поля из схемы в prompt. Оценка детерминированная; отсутствующие ответы и повторяющиеся ID считаются ошибкой. В CI команда manage.py eval проверяет набор сценариев и не вызывает внешние модели.
